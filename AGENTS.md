# Agent guidance for personal publications

## Authority and scope

This repository owns Vitalii Oborskyi's author profile, cross-project publication
index and site-owned publication editions. [CONTRIBUTING](CONTRIBUTING.md) owns
task intake, input reports and closure. [SITE-ROADMAP](SITE-ROADMAP.md) sequences
milestones; issues hold durable intent and implementation evidence.
[REPOSITORIES](REPOSITORIES.md) maps research ownership.

UA specification/research meaning remains in UA. Subprime source statuses,
report claims and operational protocols remain in Subprime. Distribution copies,
metadata, citations, generated context and public attention do not establish
research acceptance or endorsement.

## Session bootstrap

1. Verify repository/default branch, target tip and task ref; inspect the tree.
2. Discover/read root and applicable nested AGENTS in each repository touched.
3. Read owning issue's original intent, decisions, checks and dependencies.
4. For PR work inspect complete diff, base/head, feedback, checks and Draft state.
5. Read the owning source/manuscript/blueprint and publication edition/rights
   records needed for the task; fetch live sibling facts when material.
6. Use verified [RI navigation](.github/REPOSITORY-INTELLIGENCE.md) only as an aid.
   Missing/stale/ambiguous/untranslated lookup requires direct source search.
   Read complete relevant inventories before creating a competing owner.

## Issue work

Use an issue for every substantive task. Preserve initial intent; append dated
decisions and scope changes. Reuse existing inputs rather than duplicating them.
A mechanical fix may record the exception in its PR.

An issue records intent; PRs and commits implement it. For materially unclear
requested issue intent, ask focused questions and mark provisional assumptions
and open choices. Check execution against the owning issue before editing, during
review and before closure, following CONTRIBUTING. Existing decisions and routine
authorized work do not require repeated permission.

New reports, expert input, hypotheses, data and material feedback need a bounded
original-input/affected-research report for maintainer review before substantive
integration, as specified in CONTRIBUTING. Route conceptual changes to the
owning UA/Subprime issue and applicable review process. Existing explicit approval
of exact treatment may be cited; elapsed time is not approval.

Link implementation PRs with non-closing references while acceptance remains.
Summarize outcome, exact merged edition, checks, review, deviations and remaining
dependencies in both PR and issue. Close only on verified accepted completion or
an explicit reasoned reject/defer/duplicate/supersede disposition. Partial sibling
work and green CI do not complete the parent.

## Publication discipline

- Develop substantial articles with a detailed editorial blueprint and manuscript;
  reread/reconcile both after an iteration. Do not put internal process in public prose.
- Treat public copies as renditions of a named content edition; preserve immutable
  edition/source identity, canonical URL and format-specific manifests.
- Keep drafts and review previews out of public builds.
- Check figures, metrics, sources, alt text, license/credits and third-party rights.
- Distinguish public recognition from authorship, validation and institutional
  endorsement. Use exact public evidence; do not publish private exchanges.
- Inspect actual HTML/PDF/deck output on applicable screen/page sizes.
- Use pinned publishing adapters with upstream license/upgrade records; do not
  copy UA or Subprime CI wholesale or create a heavy service without a measured need.
