## Decisions

Compile the bounded canonical SVG during normal generation into numeric commands.
The browser rasterizes it once into one **1380 × 240** transparent Canvas cache,
**1,324,800 bytes** nominal RGBA, independent of viewport/DPR/theme/detail/visits.
Per visible paint it submits one drawImage command at the formula's sorted depth.
There is no runtime SVG fetch, XML parsing, text shaping, image decode or new RAF.
Diagnostics expose actual build/paint/failure counts and bounded room models.

This allowed prebuilt-vector implementation supersedes delayed Image-decode
fixtures: missing/malformed artwork fails generation atomically; cache creation
failure is contained once and preserves the rest of Canvas/HTML/navigation.
The first actual CI captures exposed heading/read-mask and ribbon occlusion at
all four widths and at 200% CSS zoom. Writing now reserves one accessible,
responsive formula band after the intro and before archive controls. Its sole
canonical SVG remains visible for no-JS/no-Canvas/Off/reduced/cache-failure modes;
the fixed scene bitmap takes over during motion. No second formula is embedded
in the global background fallback. Existing layout measurement maps the physical
band into Canvas coordinates and fixes one world landmark at depth 0.95 for the
entry/reference camera, ahead of every Color ribbon's emitted depth greater
than 1; the native near clip remains 0.5. Native scroll
and flight keep actual camera projection and continuous boundary fades; no DOM
reads occur per paint. A band below the fold at 200% zoom is inspected by real
native scroll rather than overlapping the reflowed heading. The one raster cache
is prepared within existing room/layout preparation and when motion resumes,
with cold costs retained in input-to-ready evidence. After Off/reduced, the
existing single frozen preference paint removes its native formula command
before passive artwork takes ownership; phase/camera freeze and settled zero
work remain unchanged. Resuming after disabled native scroll recalibrates in
the existing layout hook. New captures and measurements must verify this correction.
Standalone export embeds compiled runtime and all routes; it needs no external
formula asset.

The new evidence job is opt-in via exact label `site-writing-paradigm-evidence`
on same-repository PR #38, reusing `site-writing-probe.yml`. Ordinary PR updates
keep Basic/Preview. The job packages exact baseline/head Color artifacts, runs
focused Linux browser evidence then serial paired measurements, and uploads raw
JSON/captures for 90 days even on failure. It does not publish or supply full
release acceptance. Current result links belong to the issue anchor.

### 7 October 2026 protocol amendment

The first opt-in run [37609083660](https://github.com/oborskyivitalii/oborskyivitalii/actions/runs/37609083660)

change to any numeric cost, readiness, quality, cadence or paint-coverage limit.

Protocol v2 retains the immediate **4 s startup idle** and applies its original
paired p95, busy, quality, cadence and ≥90% actual paint-rate guards. Before
steady idle and each filtered/empty reflow, retain a fixed **10 s warmup** with
all callback samples and raw adaptation mutations. Its final **2 s** must be
stable with at least 10 paints and trace observations. The CPU×4 **33 ms p95 /
20% idle busy** absolute limits apply to the complete startup and every complete
warmup, as well as their original steady-state scope. No startup or warmup cost
is discarded, and a failing baseline remains a failure.

Each steady idle, bidirectional-scroll, filtered and empty window lasts **4 s**,
contains at least **20 actual paints**, and retains the observer through the
whole measured interval. Both quality/cadence snapshots and reconstructed raw
attribute old/new values must remain unchanged throughout that window; a
temporary change that returns before the end still fails. Startup, warmups,
steady windows and the original four cold/warm flights must occur chronologically
without overlap. The runner does not force runtime cadence or quality.

Reports bind `protocolVersion: 2`, the exact timing constants and the explicit
startup/warmup/steady acceptance scope. They report those three outcomes
separately; overall acceptance requires **all three** to pass. Startup retains
the original cold-readiness comparison, and all four flights retain their
unchanged transition budgets. The opted-in evidence job's 45-minute timeout
allows this transparent preconditioning; it changes no performance threshold.
Meaningful fixtures reject startup-only regressions, warmup-only absolute
failures, batched adaptive excursions, incomplete traces and overlapping windows.
Fresh exact-head browser/performance evidence and independent review are still
required after this amendment; fixture success is not a real measurement pass.

The candidate retention journey first enters normal Writing with motion enabled
and retains a **2 s positiveBeforeOff** observation with **≥8 actual paints**:
exact candidate identity, served Color runtime, raw callbacks and fresh formula
paint counters/camera.
Only then does it select Off and perform the existing five-route warmup and

paired startup trials and their original top-entry framing are unchanged.

The focused browser report also requires two actual sole-owner journeys, Off
and reduced motion. Each starts Writing with Off and an unused cache, records
