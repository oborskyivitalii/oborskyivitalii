### Where to look next

In failing pair 0, the outer painted callback starts at **8396.9ms** and ends at
**8498.9ms**. Its synchronous layout span occupies **8448.1–8496.6ms (48.5ms)**.
The cold model+initial-color preparation is **7705.3–7747.1ms (41.6ms)**, well
before this frame. Detached route cloning is 1.4ms. The second layout is 1.7ms.
Inclusive spans overlap: do not add 41.6+48.5+102 as independent CPU work.

The code calls `draw()`, then `reportTravel()`, which can synchronously mount the
route, restore native scroll and call `refresh({sync:true})`, all inside one RAF.
The remaining ~53.5ms is not fully attributed: it includes rendering and other
mount work. This points first to **route mount/native layout coupling**, not
another general-purpose geometry cache. `measurePlane` temporarily clears the
content transform to read native coordinates; the scroll restore also flushes
computed style. Measure these stages individually before batching/reusing reads.

The quality controller also consumes the whole callback cost, including route
mount. A transient DOM cost may reduce decorative detail/cadence unnecessarily.
Splitting that adaptive feedback can be useful, but the outer inclusive frame,
paint gap and input-to-ready gates must remain. Moving work out of measured RAF,
dropping paints, warming every route, or relaxing budgets is not an accepted fix.

and could be sideways or upside-down. New authoritative geometry in
`site/scenes/world.cjs` supplies closed hemispheres, cortical folds/cerebellum/stem,

The producer regenerates public hashed assets, route snapshots, native SVG
fallbacks and standalone entries. The source-derived primitive atlas provides
seven reusable SVG inspection assets. No raster asset, third-party runtime,
new scene loop or unbounded geometry is added. Small recursive copies omit
secondary guides and rails to stay within **all** old complexity limits,
including the existing 14,000 total face+line ceiling. The first fuller candidate
passed the per-kind ceiling but exceeded that older combined limit; it was
reduced before final validation, not granted a larger budget.

## Architecture and CI findings

- Source/content/scenes and generated output have clear owners; immutable
  revision/resource binding, bounded native fallback and effect API v1 should
  remain. Avoid another framework or renderer migration without a measured need.
- The bounded room/model/palette caches and one final depth sort address real
  duplicate work. The next hotspot is the main-thread route/layout transaction.
- The supposedly minimal PR profile still had a second large suite in
  `navigation.yml` (Python, theme/space/archive, preview/content, export/ZIP).
  This review removes those duplicate runs there; RI freshness remains. The one
  basic site suite stays at 10 tests. Complete suites are retained in the hosted
  release build; no security/browser/performance acceptance gate is removed.
- The first #18 run exposed a further path-triggered Windows/Firefox
  `site-navigation-probe.yml`. It is now manual-only, as its name/intended
  diagnostic role implies. The first-head run remains in history; it is not
  presented as part of the minimal profile on the corrected head.
- Staging's caller, trust checker, recovery checks and comment target still
  hardcode **open PR #10 / old branch**. After merge, entering credentials cannot
  make that recipe valid. The updated [runbook](../../SITE-STAGING.md) explicitly
  documents the required protected-main/source-identity migration before any
  activation. Both false guards remain; no live URL is invented.
