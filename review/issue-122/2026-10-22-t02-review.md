### WB-T02-02 — Medium, blocking: digest serialization is not uniquely defined for allowed Unicode

**Location:** `guides/SITE-CHECK-PROFILES.md`, lines315–321 and341–346.

The contract allows exact UTF-8 paths and defines digests through compact UTF-8 JSON with lexical sorting, but leaves Unicode escaping and the sorting comparator unspecified. Both literal `é` and `\u00e9` are valid compact JSON encodings written as UTF-8. Different producers can therefore hash the same declared file records differently. Locale, UTF-16 and Unicode-code-point ordering can likewise differ for otherwise valid paths/keys.

**Executed counterexample:** Python serialized `[["guides/é.md", "a" repeated64]]` with compact separators, no trailing newline and either `ensure_ascii=False` or `True`. Both meet the current textual convention. Their SHA256 values are respectively `83184071aa4a8d64d5abfd675bd769c15b26903ab5756dfb21610202b3345608` and `ab9d0bb608398b98cf2689d08188ff65a8750ef9774e4695379b3ceba9cff611`.

**AC impact:** T02.2 deterministic policy/protection identity and invalidation become ambiguous; this is a contract defect, not an executed future-classifier failure.

**Treatment:** Specify one complete canonical serialization convention covering string escapes, path/object-key ordering and permitted JSON values, consistently for policy and protection digests. A concise defined convention or precisely adopted canonical format suffices. Do not add an unused serializer implementation in T02.
