## Proposed experience

The normal first visible viewport is immediately settled. Below-fold blocks are
armed only after successful setup and a stable native landing. With ordinary
downward reading, a stable shell crossing a lower activation band starts a single
short upward movement; it remains settled once read. Upward reading never hides
blocks. This is a trigger-based animation, not continuous scroll scrubbing.
These are proposed design defaults, not an additional maintainer instruction.

| Parameter | Desktop start | Narrow start | Bound / reason |
| --- | --- | --- | --- |
| Vertical displacement | 88 CSS px | 56 CSS px | Visible travel without moving a viewport of text |
| Duration | 560 ms | 440 ms | Quick settling; tune from actual visual review |
| Ease | `cubic-bezier(0.22, 1, 0.36, 1)` | Same | Monotone ease-out, no overshoot |
| Activation band | Approximately lower 8–12% of viewport | Same | Use shell entry, not a large area threshold that excludes tall blocks |
| Sibling delay | Up to 80 ms | Up to 60 ms | Group tail at most 160 ms; never index the entire archive |
| Text/backdrop opacity | Unchanged | Unchanged | Crisp, opaque text; original shared backdrop alpha |
| Active work | Visible entering set | Visible entering set | Settle rather than queue work beyond the measured cap |

No scale, perspective, blur, letter fragmentation or elastic bounce is needed for
this request. Whole-block movement supplies the requested entry. Keep first-fold
headings, header, skip link, nav/filter controls, footer and next-route controls
steady. Preserve all five routes, existing colors and reading-surface parameters.

Use explicit template markers/existing semantic component selectors as the
eligibility contract, and runtime-owned data states. Do not derive targets from
arbitrary DOM text or reuse the camera's semantic stop attribute as animation
eligibility. Do not insert an illegal wrapper between an `ol` and its `li`.
Where an existing inner layer is available, move it inside the stable shell;
add a minimal canonical template layer only when geometry and byte budgets allow.
Other direct-child selectors need focused review; no new surface parameters or
per-route paint override belongs in entry CSS.

Writing specifically cannot afford serialized row wrappers/markers: its current
99,997-byte root HTML has three bytes of headroom under the 100,000-byte limit.
Use the existing `li.publication` contract to identify units, retaining the li's
grid/filter/measurement identity. Its existing meta and copy children, together
with its existing `::before` paper surface, receive the same keyframe, start,
delay, duration and displacement from one row state. Shared reading CSS remains
the paint owner; this is one visual unit with synchronized existing layers.
No authored inline CSS or new public content enters the controller. Test those
layers' alignment at intermediate frames, not just their equal final transforms.
Prefer this zero-additional-HTML treatment for other existing full-row cards when
it preserves their measurement and paint contracts too. Do not raise budgets,
minify arbitrary authored markup or omit Writing to make this plan fit.

Observe and measure the untransformed shell. Its layout footprint and anchor
position stay native. That alone does **not** guarantee stable scroll height:
[CSS Transforms](https://www.w3.org/TR/css-transforms-1/#transform-rendering)
specifies transformed overflow as well as normal layout. Bound transient paint
overflow locally, with allowances for the existing surface gutter, title outset
and focus outline, and release temporary containment when settled. Prove this
on active frames at the document bottom and in narrow layouts. Do not silently
use overflow:hidden if it creates an internal scroll container or clips ink.
If a proposed wrapper cannot preserve these invariants, revise it before
enabling that unit; skipping a promised route is not whole-AC acceptance.

## Controller and integration architecture

Proposed single authored owner: `site/engine/scroll-entry.cjs`, exporting a
closure-safe browser factory. The build composes it with `navigation.js` using
the existing explicit factory/producer pattern. Pure inputs include environment,
motion-state query and canonical marker contract; no imports of build tools,
generated output or an implicit require side effect. CSS/static parameters live
in `site/engine/scroll-entry.css`, concatenated by the existing stylesheet owner.
Both new sources participate in fingerprints, scanner inventory and catalog.

The factory exposes `mount(main, landing)`, `suspend()`, `resume()`, `settle(target)`
and `destroy()`. One session owns the observer, data states, active animations and
listener cleanup. A generation token rejects callbacks after navigation; a new
mount resets ephemeral state on reused nodes. CSS keyframes do the movement:
pending/entering/settled data states do not generate per-frame DOM mutations.
Settle cancels visual work and removes only controller-owned state. Unknown or
failed capability defaults to fully visible native content.

An IntersectionObserver watches stable shells with a viewport root. Its
[specification](https://www.w3.org/TR/intersection-observer/) delivers threshold
observations asynchronously; it does not guarantee an immediate animation frame.
Arm wholly offscreen blocks early enough to prevent a native-then-shifted flash,
observe a low entry threshold to support tall blocks, and batch initial native
measurements before arming. A passive scroll listener may record native offset,
direction and jump size only; no preventDefault, polling, whole-page rect reads
or per-frame transform writes. Large/programmatic jumps settle the new visible
viewport instead of scheduling late entry animations.

| Boundary | Integration / invariant |
| --- | --- |
| Initial document | Initialize after archive/native landing and existing DOM readiness. Bootstrap must also work when the router takes its unsupported-capability early return. First visible viewport and direct hash landing settle; no dependence on a canTravel value sampled before scene initialization. |
| Navigation start | Suspend and settle outgoing entry before travel presentation or future fragment capture. Invalidate async callbacks without taking ownership of router serial/history/input tails. |
| Native replacement | Destroy old session before `replaceChildren`; prepare new session after archive/filter/scroll/anchor work and native layout. Keep it suspended through any remaining route flight. |
| Actual arrival | Resume only inside the current serial's successful post-flight completion, after presentation cleanup. If adding an event, it must describe this boundary; page-ready is insufficient. |
| Interruption / instant route / failure | Settle current content; resume only the surviving mounted route, or preserve ordinary document fallback. Ensure exceptions cannot leave pending visual states. |
| Archive filter/reset/history | Use the existing layout notification with a bounded deferred reconciliation after synchronous landing. Hidden rows are never animated; newly visible viewport rows settle; previously settled rows do not reset. |
| Focus / anchors / large jumps | Settle target and its relevant block before keyboard interaction or anchor measurement. Same-page native anchors need a pre-landing settle path too. Browser find remains visible; verify real behavior instead of assuming beforematch applies to ordinary text. |
| Resize / font reflow | Reconcile eligibility from stable shell geometry after the existing reflow, never rerun a completed entry. Retain readable wrapping and actual bottom. |
| Motion / hold / failure | Existing lifecycle owns preference. Add only a narrow effective-state accessor/notification where needed for initialization, held/still and failed states; no second storage writer or independent quality adaptation. Disabled content settles immediately. |
| Print / hidden / pagehide / bfcache | Clear or finish active entry; print includes all native content. On pageshow, retain one session/listener set and settle restored visible viewport, without a queued animation burst. |

Do not add permanent will-change or persistent transform promotion to every
archive row. Use promotion only for bounded entering units if measurements show
it helps, then remove it. CSS animation is not itself proof of compositor use,
smoothness, unchanged scroll range or reduced CPU work.

## Verification and proposed failure coverage

Add entry-state behavioral tests to the maintained source registry only when the
runtime exists. Do not add a test that merely searches these documents for the
recommended method names. Before readiness, replace preparation-only gates with
named executable tests plus the remaining visual/device decisions.

- Controller: visible-on-boot, late initialization, unsupported APIs/errors,
  initial/direct-hash/restored landing, normal down/up, tall rows, large jumps,
  reverse while entering, active-cap saturation, sibling delay bound, animation
  finish/cancel, stale observer callback and repeated mount/disposal.
- Geometry: measured shell/marker/first Writing row stays fixed; native range,
  bottom reach, width and wrapping agree with entry disabled, sampled while
  moving and settled. Test the last block, pseudo backdrop gutters and focused
  links at narrow widths; do not infer overflow safety from no CLS alone.
- Router/archive: preserve current route-wide presentation, interruption,
  instant/Off navigation, Back/Forward, cached node reuse, deep links, filters,
  reset/empty archive, resize/font changes and hidden/print/bfcache behavior.
- Delivery: exact shared hosted base/Color and standalone controller source,
  normal no-JS/no-Canvas content, immutable output freshness and no second asset
  fetch, texture capture or scene animation loop. Preserve the 100,000-byte raw
  HTML limit: Writing's zero-additional-markup design is required by the actual
  99,997-byte baseline, not an assumed amount of available space.
- Performance: opt-in existing layout/paint probes distinguish scene redraw
  from repeated layout; no layout pass per entry frame, bounded live nodes and
  zero callbacks after disposal. Measure actual added cost on matching source,
  viewport/browser/CPU conditions; report failed trials instead of raising limits.

Reuse `navigation.test.cjs`, `archive.test.cjs`, `scroll-sync.test.cjs`,
`site-engine.test.cjs`, `effects.test.cjs` and their registered browser companions
where their existing assertions apply. Entry-specific cases extend these routes
or one narrow registered suite, not a parallel whole-site harness.
Normal PR feedback uses Basic/source/RI/owning-policy and ordinary preview.
Hosted runtime admission uses the existing bounded staging route when authorized,
with the existing 33ms paint callback p95, idle busy limit and transition limits
from `tools/quality/budgets.json`; entry does not introduce a reason to relax them.
Physical iPad smoothness and native production device evidence remain separate.
