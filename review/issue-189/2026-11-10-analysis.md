## Current architecture and failure mechanism

1. scan() walks supported files, hashes all nonderived input bytes (including HTML/JS/assets/archives), decodes bounded text, and checks tracked exclusions/modes.
2. path_inventory() requires exact catalog coverage of files and ancestor directories, purposes, roles and existing editing owners.
3. build() constructs one complete projection with source identities, owner aliases, instructions, artifacts/directories and validation routes.
4. render_map() prints the entire inventory into REPOSITORY-MAP.md. JSON also retains the complete projection.
5. verify() rebuilds the source projection and compares parsed JSON plus map text. Every query/context command invokes this full verification first.
6. GitHub issues/refs/checks/deployments remain a separate live overlay; RI cannot establish current delivery or acceptance.

Thus there are two independent problems: excessive **default reading volume** and almost exhausted **physical hash-input capacity**. Shrinking the two existing derived outputs helps context size, but does not save bytes under the 250MB input cap. ## Proposed architecture: keep two outputs and one producer

Retain Git, Markdown, the canonical catalog and current RI CLI. No database, vector store, new service, generated shard tree, remote archive store or new persistent cache.

- **Authored owners:** repository-paths.json owns purposes/roles/editing ownership; repository-intelligence-config.json owns concern aliases, validation routes and continuity settings. Do not maintain a second parallel list of task history.
- **Complete projection:** keep agent-context.json at its existing path and preserve existing schema2 fields, source_identity.digest and full artifacts/directories/inputs. This remains the complete machine/navigation inventory and CI identity surface, not a file to paste wholesale into every chat.
- **Short entry:** change REPOSITORY-MAP.md from exhaustive dump to a deterministic current-repository entry, generated from those same owners. Include root entry routes, current areas/canonical owners, applicable instruction/check entrypoints, explicit current/history lookup recipes and direct-source fallback for connector-only agents. Proposed hard budget32,768 UTF-8 bytes. A rough concern/check rendering from current configuration is5,519bytes; that is feasibility evidence, not a finished map.
- **Scoped reads:** add optional current/history/all scope and exact prefix/file filtering to the existing CLI. The recommended map/agent route uses explicit current scope. Preserve legacy unqualified query/inventory behavior for compatibility; do not silently change existing API results. Current excludes history/draft/generated artifact roles but never filters the complete stored projection or freshness scan. Historical and generated paths remain explicitly accessible.
- **Bounded results:** opt-in scoped queries expose a stable page limit (proposed20 artifact/directory hits), returned/remaining counts, continuation position, verified source digest and explicit unresolved/fallback state. Never present a truncated list as complete. Prefix matching is path-component aware; exact file/directory requests retain all applicable instructions and check routes, including directory-only matches. Existing query result fields remain available; additive metadata is reviewed against real consumers. Paging applies only to artifact/directory hits ordered deterministically by (kind,path); complete applicable instruction/owner/check-route metadata must never be paged away. The20-hit count is explicitly only a list bound, not a total-response byte limit: measure complete broad-alias and normal-task responses separately; never drop applicable instruction/check metadata to force a byte target. Report a need to narrow or read direct sources where excessive. Continuation uses explicit offset plus a request fingerprint binding normalized query, scope, exact prefix, page size and verified source digest; reject reuse after any bound input changes. No persistent cursor service or cache is added.
- **Integrity:** keep full input hashing and all existing bounds. Canonical serialization verification for generated JSON/map will compare regenerated bytes; current JSON equality is semantic and does not detect whitespace-only edits. No recursive self-hashing or new derived-output family is needed.
- **Instruction safety:** live scoped instructions remain discovered and routed. Loose historical AGENTS.md must not become active because of its basename: reject contradictory history/draft classification for such a live-name file and require an inert archive name or compressed member. Do not silently let a role label suppress a live applicable instruction. The current tree has only root AGENTS.md; this is a negative-boundary requirement, not an observed incident.
- **Capacity visibility:** extend existing tooling with a small read-only capacity report if needed; report file count, aggregate hash/text, maxima and individual margins, output bytes and top contributors. A warning below10,000,000bytes aggregate headroom is advisory; the existing hard limits remain the only refusal thresholds.
